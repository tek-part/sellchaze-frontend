# Theme + Sections Contract (Salla-style customizer)

Single source of truth for the 2026-09 theme/section work. Frontend (`sellchaze-frontend`) owns the
section library, theme modules and the manifest export; backend (`sellchaze-backend`) owns persistence,
publishing and the public layout API. Both must follow the shapes below exactly.

## 1. Section schema (frontend TS, `src/apps/storefront/sections-lib/schema.ts`)

```ts
export type SettingFieldType =
  | 'text' | 'textarea' | 'richtext' | 'color' | 'select' | 'image' | 'url'
  | 'toggle' | 'number' | 'range' | 'list' | 'product' | 'category' | 'collection';

export interface SettingField {
  id: string; type: SettingFieldType; label: string; hint?: string; group?: string;
  default?: unknown;                    // scalar, {ar,en} for translatable text, array for list
  options?: { value: string; label: string }[];   // select
  min?: number; max?: number; step?: number;      // number/range/list(max items)
  translatable?: boolean;               // text/textarea/richtext: value may be string | {ar:string,en:string}
  item?: SettingField[];                // list: fields of each item (no nested lists)
  responsive?: boolean;                 // range with css_property → per-viewport override
  css_property?: 'padding-block'|'padding-inline'|'margin-block'|'gap'|'font-size';
}

export interface SectionSchema {
  type: string;                         // kebab-case, unique across the library
  label: string; description?: string;
  category: 'hero' | 'products' | 'categories' | 'content' | 'marketing' | 'social' | 'layout';
  icon?: string;                        // react-icons/hi2 name, e.g. 'HiOutlinePhoto'
  settings: SettingField[];
  presets?: { label: string; settings: Record<string, unknown> }[];
}
```

Section VALUES: `settings[fieldId]` is a scalar, a localized map, or (for `list`) an array of objects keyed
by the item field ids. Product/category/collection fields hold the referenced id/slug as a string.

Section components receive the engine's `SectionRenderProps`. Every rendered section root element MUST
carry `data-section-id={instance.id}` and `data-section-type={instance.type}` (the engine's
`ThemeRenderer` wrapper does this; do not duplicate).

## 2. Backend `sections_schema` JSON (theme manifest `resources/themes/storefront/<key>.json`)

Generated by `npm run themes:manifests` from the theme module — never hand-edit generated files.

```json
"sections_schema": {
  "<type>": { "label": "...", "description": "...", "category": "hero", "icon": "HiOutlinePhoto",
              "settings": [ <SettingField JSON, options as [{value,label}]> ] }
},
"settings_schema": [ { "id": "<group>", "label": "...", "fields": [ <SettingField JSON> ] } ],
"templates": { "home": {"sections":[{"type":"...","settings":{...}}]}, "product": {...}, "category": {...} }
```

Backend validators must accept: `list` values as arrays of objects; `select` options as either bare
strings (legacy manifests) or `{value,label}` objects; `translatable` text as string or locale map.

## 3. Home layout persistence (backend)

* `store_pages.template` gains `'home'` (and stays `page|landing` for custom pages). Exactly one
  `home` page per (store, locale); slug `home`; it is never served at `/pages/home`.
* `GET  /api/v1/{my-store|stores/{store}}/pages/template/home` → ensures the home page exists (seeded
  from the active theme's manifest `templates.home` with `SectionRegistry::resolveSections` ids) and
  returns the standard page payload (`pageArray`, incl. `sections[]` and `has_unpublished_changes`).
  Optional `?locale=`.
* All existing page endpoints work on it: `PUT pages/{id}/sections`, `PUT pages/{id}`,
  `POST pages/{id}/publish|unpublish`, `GET pages/{id}/revisions`, restore.
* `GET pages/schema` returns `{ sections_schema, theme:{key,version}, settings_schema }` — the
  `sections_schema` entries carry `label, description, category, icon, settings`.

## 4. Public layout API (backend → storefront SPA)

* `GET /api/v1/storefront/layout?template=home` (resolve.store + storefront.locale middleware)
  → `{ "data": { "template":"home", "source":"store"|"theme", "page_id": 12|null,
                 "sections":[ { "id":"published-0", "type":"hero", "settings":{...} } ] } }`
  Uses the PUBLISHED snapshot of the store's home page for the request locale (fallback: default
  locale's home page, then the active theme manifest `templates.home`). Hidden sections are omitted.
  Cached with the storefront page cache; invalidated on publish.
* `GET /api/v1/storefront/pages/{slug}` → `{ "data": { "title","slug","template","seo",
  "sections":[...] } }` for published custom pages (`page|landing`), 404 otherwise.

## 5. Live customizer preview (postMessage)

Storefront SPA URL for the customizer iframe: `<storefront origin>/?preview=1&customize=1&lang=<locale>`
(dev: `http://localhost:5173/?preview=1&customize=1`; VITE_STOREFRONT_HOST already proxies the tenant).
Optional `&theme=<key>` to preview a theme that is installed but not active.

* SPA → editor on mount: `{ channel:'sellchaze-theme-preview', version:1, type:'ready' }`.
* Editor → SPA: `{ channel:'sellchaze-theme-studio', version:1, type:'hydrate',
  payload:{ sections:[{id,type,settings,is_visible}], locale:'ar'|'en', path:'/', settings?:{...theme settings draft} } }`
  The SPA re-renders the home template from `payload.sections` (visible only) without reload and applies
  `payload.settings` through `resolveSettings` if present; `path` may be `/pages/<slug>` for custom pages.
* Editor → SPA: `{ type:'select-section', payload:{ id } }` → SPA scrolls to `[data-section-id=id]` and
  adds class `is-customizer-selected` (outline).
* SPA → editor on click of a section in customize mode: `{ channel:'sellchaze-theme-preview',
  version:1, type:'section-selected', payload:{ id } }`.
* Types live in `src/apps/storefront/platform/studio/editor-domain.ts` (extend, do not fork).

## 6. Theme module conventions (the five new themes)

Folder `src/apps/storefront/themes/<id>/` with: `manifest.ts`, `settings.ts` (fields carry `group`),
`tokens.ts`, `index.ts` (exports `<camel>Theme: ThemeModule` + default), `layouts/DefaultLayout.tsx`
(+ `layouts/index.ts`), `chrome/` (Header, Footer, MobileNav, CartDrawer, SearchOverlay, AnnouncementBar),
`theme.css` (skin: only `var(--token)` values; class prefix unique per theme), `templates.ts`
(home/product/category + the shared extra templates from `sections-lib/templates.ts`).
Sections come from the library: `sections: createSectionMap()` (optionally overriding a few types with
theme-specific components). Manifest: `previewImage: '/media/theme-previews/<id>.jpg'`,
`schemaVersion: 2`, `supports.colorSchemes`, `capabilities`, `minEngineVersion: '1.0.0'`.
Register in `src/apps/storefront/platform/catalog/catalog.ts` and add the alias-free key to the backend by
running `npm run themes:manifests` (writes `../sellchaze-backend/resources/themes/storefront/<id>.json`)
then `php artisan themes:register` in the backend.

Shared pages (auth, account, cart, checkout, wishlist, static, 404) import the foundation primitives
(`src/apps/storefront/foundation/components`, skinned app-level by `foundation/base.css` + `pages.css`);
each theme ships `shared.css` overrides for the `.sf-*` classes it needs to reskin, like
`themes/naseem/shared.css`.
