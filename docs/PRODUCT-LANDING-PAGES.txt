Product landing pages

The merchant product editor opens /store/products/:productId/landing in a separate,
full-viewport editor. Admin store scope uses /stores/:id/products/:productId/landing.
The shell requires products-edit in owner scope; it does not grant theme access.

The editor uses a 73px toolbar, a 320px right element pane, a separate 364px left
properties pane, Almarai, and a 300ms pane
transition with reduced-motion support. It provides eighteen element families,
twenty-four render types, explicit save, undo/redo, movement, duplication, removal,
read-only preview, a narrow canvas, and native Sellchaze JSON import/export.
Uploaded JPG/PNG/GIF/WebP images are product-owned and limited to 10MB each.

Layout modes are standard (retain the document without displaying it), standalone,
and below the conventional product presentation. Products without a document keep
their existing theme presentation. A standalone layout without a checkout block
retains the conventional purchase fallback. Multiple checkout blocks render one
live form and subsequent purchase links, with shared variant, quantity, offer and
personalization choices. Real checkout reuses authoritative quotes, shipping,
inventory, payment recovery, contact fields, minimums, OTP and bot protection.
The ordinary basket is preserved. A direct checkout URL reports the storefront
surface; embedded product checkout reports the product surface for advertising.

Static merchant HTML/CSS renders only in an opaque sandboxed frame with a CSP,
not in the dashboard or storefront DOM. The trusted bridge accepts size/scroll
messages only from its own frame. The purchase bridge only scrolls to the live
purchase section. It never submits an order or uses HTML-provided prices.

The API returns a version hash. Concurrent different edits fail without replacing
the local draft. Retrying the exact accepted canonical document is safe. Product
metadata and inventory do not change its document version. Export strips owned
media identities into URLs; catalog duplication remaps owned media to the copy.

Backend migration 2026_10_16_030000_add_product_landing_pages.php is required before
this frontend. It adds a nullable document and leaves existing product rows intact.

Scope still in progress: exact reference layouts for all twenty-two product
templates, deeper per-family reference controls, source-format landing conversion,
and activated AI authoring. Native page-file import is not a claim that competitor
template files or private layouts can be imported. This change does not activate
AI, billing, payments or production deployment.

Eleven custom testimonial designs can be selected or changed without replacing
merchant items. They include carousels, centered quotes, colored cards, a grid,
two animated rows and speech bubbles. The gallery uses neutral preview-only data;
empty published sections do not invent reviews, ratings or verified buyers.
Author, optional date/caption/platform, accent and card colors persist with the
layout. Motion pauses on hover/focus, has a pause control and honors reduced motion.
Section background images use the same owned-media validation, portability and
copy remapping as foreground images. FAQ question backgrounds are configurable.
Cleared optional text fields remain empty after JSON middleware normalization.
The storefront also accepts PHP's empty settings-map JSON representation ([]).

Nine promotional image layouts are available through a native diagram gallery.
Selecting a new layout preserves all merchant images and destinations, pads empty
editor slots when needed, and keeps extra images in additional groups. Public
rendering never substitutes demo photos. Image panels use cover fitting,28px
corners,20px gaps, responsive columns and a reduced-motion-aware load animation.
Clicking an image in the editor opens its item properties without following links.

Banner images may target an own-store product, category or published page. The
products-edit destination endpoint returns only bounded public-safe labels/URLs,
with literal search, pagination and selected-item recovery. Stored references
follow current public paths and become unlinked if unavailable; drafts/foreign
entities are not exposed. Published page labels use publication snapshots.
Native page/catalog exports replace references with portable URLs. Exported files carry URLs instead of numeric destination identities; ordinary
duplication retains existing links
and remaps image ownership. Unavailable destinations must be fixed before native
page export. The existing landing migration is required; this phase adds no tables.

Forty-five store-feature presets now cover bordered cards, unboxed benefits,
horizontal pills, a split heading/grid, logo rows, merchant-entered numbers,
a standalone statement and three15-second tickers. The gallery is drawn natively;
it contains no competitor images, CSS, brands, sample policies or fake metrics.
Changing a design preserves item identity/order, text, icon, image and link, pads
only blank editor slots and never truncates extra merchant items. Compact designs
can omit descriptions/headings/images visually; their stored content is retained.
Numbers are merchant-entered text, not inferred live statistics. Empty published
presets never use the editor's neutral examples. Each item has a selectable symbol
or owned image, optional link/colors and reorder controls; image clicks target the
item inspector. Section colors include icon, card, description and hover states.
Motion can be disabled; tickers offer pause/resume, keep copies inert/link-free,
and wrap the real content under reduced motion. Native catalog/page transfer and
product duplication retain all fields and remap owned images. No new migration.
These presets do not establish full public/font/phone parity for the wider catalog.

Thirty-five FAQ presets add single-column, two-column and split heading/group
structures, capsules, dashed outlines, bottom rules, offset shadows, gradient
headings and distinct section/group/card paints. The native accessible diagram
gallery includes no reference images or sample commercial policies. Blank slots
remain blank in saved data. Existing FAQ sections without a variant keep their
original rendering. Changing a FAQ preset retains all questions, answers, rich
HTML, owned images, URLs, colors and extra items; an explicit reset restores the
preset colors/typography. Presets1/34 start with3/4 slots; the others start with6.
Each accordion opens one answer at a time, supports Enter/Space and arrow/Home/End
focus navigation, and associates each question with a unique answer region.
Closed answers are inert and hidden from assistive technology. Intrinsic-height
expansion uses250ms easing; reduced motion or the section motion setting disables
transitions. Clicking a question in the editor opens its own question/answer
inspector without blocking the accordion. Save, undo, reordering and native page/
catalog transfer preserve the document and remap owned images. The purchase form
remains singular. FAQ colors and static answer HTML use existing validation and
isolation; no new migration. Source phone/public typography fidelity remains an
explicit separate acceptance task for the broader catalog.
Paired backend text handling retains leading/trailing whitespace and newlines in
landing document text so saving and undoing edits cannot rewrite untouched answers.
